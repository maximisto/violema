# October 16 not-found release: activated

violema.com stops serving the old workspace app, which moved to agent.purpleorange.ai. Unknown paths and every old
workspace page or asset return a real 404 with the company `404.html`. Only `/api/` still proxies to the backend on
127.0.0.1:3001, for the Google OAuth callback and the Stripe and Postmark webhooks. Max approved it and it was
activated on 2026-10-16 as release `20261016-d673fe0-not-found`. This folder records how; nothing here runs in CI.

## What changed

- **Site source:** commit `d673fe0cfcef51444e1a2e5dccaf71831ae67c75` adds `404.html` (site header and footer,
  noindex, no canonical, root-absolute links) and drops the links to `/login`, `/terms` and `/privacy`. The other 52
  built files are byte-identical to the previous release.
- **vhost** (`vhost.diff`, generated by `make_candidate.py`): a marked `VIOLEMA NOT FOUND` block inside the company
  overlay sets `error_page 404 /404.html`, serves that page `internal` with the overlay's security headers and
  `no-cache`, and serves `/index.html` as the company home. The old SPA block (its root, static-asset regex and
  catch-all) becomes `location / { return 404; }`. `/api/` is unchanged and `proxy_intercept_errors` stays off, so
  backend errors pass through.

## Files

- `make_candidate.py <baseline> <candidate>`: refuses unless the baseline matches its pin, then applies the two
  edits, each asserted to match exactly once.
- `activate.py <staged-dir> <release-id>`: refuses on vhost, candidate, manifest or release-pointer drift, checks
  every archive member against the manifest and the public allowlist, backs up to
  `/var/backups/violema-science/<release-id>/`, runs `nginx -t`, reloads, then retries the post-checks up to 15
  times. Any failure restores the vhost and the release pointer and reloads again. It never touches PM2.
- `vhost.diff`: the reviewed change, baseline to candidate.

The staged directory also held `baseline-violema.conf`, `candidate-violema.conf`, `manifest.json` and
`public-dist.tar.gz`. They are not committed: the vhosts are server config and the tarball is a build output. Both
are reproducible from the pins above (`npm --prefix company-site run build` at the source revision, and
`make_candidate.py` on the pinned baseline). The vhosts contain no key material, only certificate file paths.

## Rollback

Restore `/etc/nginx/sites-available/violema.com` from
`/var/backups/violema-science/20261016-d673fe0-not-found/baseline-violema.conf`, point
`/var/www/violema-science/current` back at `releases/20261016-5f22dc2-umami-3`, run `nginx -t`, then reload nginx.
